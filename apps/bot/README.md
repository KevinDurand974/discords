# bot

On Windows, `nub run start` / `nub run dev` may launch a nested `cmd.exe` batch script even from Warp Bash. If Ctrl+C shows `Terminate batch job (Y/N)?`, type `Y` and Enter, or bypass the script shell from `apps/bot` with `nub src/index.ts` (start) or `nub watch src/index.ts` (dev). You can also use `nub run --script-shell bash start` / `nub run --script-shell bash dev` to keep the package scripts while selecting Bash explicitly.

## Netmarble news Forum (Phases 4–5)

Set `DATABASE_URL` in the untracked `apps/bot/.env` to the same PostgreSQL database used by the API, and set `NEWS_API_URL` to the public API base URL (`http://localhost:3000` by default). Run `nub --cwd apps/bot exec varlock run --inject vars -- nub --cwd ../.. run db:migrate` before starting the bot. Deploy the updated `/setup` command with `nub --cwd apps/bot run sync` (configure `DISCORD_GUILD_ID` for guild command deployment). Start the API before the bot (`nub --cwd apps/bot run start`); the source must have finished its first ingestion. The bot still runs outside Compose.

On a Community-enabled server, an administrator with **Manage Channels** can run `/setup news create`. The bot needs Manage Channels, Manage Roles, Manage Threads, Send Messages, Send Messages in Threads, Embed Links, Attach Files, Read Message History, and Mention Everyone; its role must be above `@everyone`. It creates one read-only-with-comments Forum, five category tags, and five non-mentionable, manually assigned `SLA:` roles. The command is idempotent while enabled; if disabled it reactivates the existing resources. `/setup news status` reports the channel and mappings, and `/setup news disable` turns off future publication without deleting resources. If saved resources were deleted manually, reactivate only after repairing the configuration in PostgreSQL.

`/setup news create [import-mode: backfill|future-only] [backfill-count: 1..50]` imports the 10 newest articles plus currently source-pinned articles by default. Future-only marks existing normal articles as skipped and imports pinned articles without notifications. `/setup news backfill [count: 1..50]` imports previously skipped historical articles. Only newly discovered live articles mention their matching `SLA:` role. Both setup and manual backfills are silent. The bot synchronizes every 30 minutes and once at startup, using the public API. After the initial import, automatic runs publish missing articles only among the 10 newest across all five categories; use manual backfill to import older articles. New posts include the matching tag, Markdown details and one canonical Netmarble link button. Article text and inline images use Components V2 (Text Display and Media Gallery); table rows use individual Components V2 containers, with two labeled areas separated visually. If an article begins with a table, its opening V2 message contains the canonical link (and any notification), followed by the row containers. The bot reconciles the Forum pin on every complete source synchronization without reposting: the newest source-pinned Notices article takes priority, otherwise the newest source pin. A category listing failure does not prevent healthy categories from publishing or clear existing pins; pin reconciliation retries on the next complete poll. Long article text is split into Discord-sized messages; oversized formatted text falls back to escaped plain text with source links preserved. Inline article images are uploaded in reading order when valid; otherwise the original URL is shown at their position. HTML table headers are shown inside the row areas rather than as separate rows; rows connected by a `rowspan` become one container with a bullet list on the right. Table-cell images appear as thumbnails beside the left area. Each 📌 begins a Discord `##` subheading with two blank lines before it; ※ notes become quotes, and leading * notes use small text. No unsupported Markdown tables are emitted. HTML strikethrough uses Discord's `~~text~~`. Existing `/setup logs` is unchanged.
