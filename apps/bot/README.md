# bot

On Windows, `nub run start` / `nub run dev` may launch a nested `cmd.exe` batch script even from Warp Bash. If Ctrl+C shows `Terminate batch job (Y/N)?`, type `Y` and Enter, or bypass the script shell from `apps/bot` with `nub src/index.ts` (start) or `nub watch src/index.ts` (dev). You can also use `nub run --script-shell bash start` / `nub run --script-shell bash dev` to keep the package scripts while selecting Bash explicitly.

## YouTube Latest Videos

`/videos add [backfill-count:0..15]` opens a channel URL/`@handle`/`UC...` modal, creates the managed **Latest Videos** Forum when needed, reuses creator tags and imports ten videos by default. `/videos status` reports progress; `/videos sync` publishes pending stored sources; `/videos clean` is administrator-only and requires an expiring confirmation. There is no Content Creator role. Manage Messages authorizes management and post creation; human comments are denied, except Discord's Administrator bypass.

Use the same `DATABASE_URL` and `NEWS_INTERNAL_TOKEN` as the API; `YOUTUBE_API_URL` optionally overrides `NEWS_API_URL`. `YOUTUBE_API_KEY` remains API-only. BullMQ refreshes RSS then publishes every ten minutes, including Shorts/livestreams. See [`docs/youtube-videos-operations.md`](../../docs/youtube-videos-operations.md) for staging validation, owned overwrite policy, tag capacity, cleanup and recovery. Live Discord permissions/V2 rendering must be verified before production deployment.

## Netmarble news Forum (Phases 4–8)

Set `DATABASE_URL` in the untracked `apps/bot/.env` to the same PostgreSQL database used by the API, and set `NEWS_API_URL` to the public API base URL (`http://localhost:3000` by default). Run `nub --cwd apps/bot exec varlock run --inject vars -- nub --cwd ../.. run db:migrate` before starting the bot. Deploy the updated `/setup` command with `nub --cwd apps/bot run sync` (configure `DISCORD_GUILD_ID` for guild command deployment). Start the API before the bot (`nub --cwd apps/bot run start`); the source must have finished its first ingestion. The bot can also run in Compose with `nub run docker:bot:up` after setting a shared `NEWS_INTERNAL_TOKEN` in `apps/api/.env` and Discord credentials in `apps/bot/.env`; this profile is opt-in. The bot exposes container-local `/health/live` and `/health/ready` on port 3001; readiness checks Discord and PostgreSQL and returns durable per-guild last publication timestamps. See `docs/netmarble-news-operations.md` for restart and recovery.

On a Community-enabled server, an administrator with **Manage Channels** can run `/setup news create`. The bot needs Manage Channels, Manage Roles, Manage Threads, Send Messages, Send Messages in Threads, Embed Links, Attach Files, Read Message History, and Mention Everyone; its role must be above `@everyone`. It creates one read-only-with-comments Forum, five category tags, and five non-mentionable, manually assigned `SLA:` roles. The command is idempotent while enabled; if disabled it reactivates the existing resources. `/setup news status` reports the channel and mappings, and `/setup news disable` turns off future publication without deleting resources. If saved resources were deleted manually, reactivate only after repairing the configuration in PostgreSQL. `/setup news clean` is **administrator-only** and requires a second, ephemeral confirmation naming the stored Forum ID, notification role IDs, and publication-history count. It pauses and drains guild sync before deleting only those saved Discord resources, then removes this guild's mappings and history from PostgreSQL. Forum posts, comments, attachments and role assignments cannot be restored by a subsequent create. Missing resources are treated as already removed; on partial failure the saved IDs remain for a safe retry with `/setup news clean`. After success, `/setup news create` provisions new roles/Forum and repeats the configured initial import.

`/setup news create [backfill-count: 0..10]` imports the 10 newest articles excluding the preferred pin, plus at most one preferred source-pinned article, by default. Set `backfill-count` to `1..10` to select the initial history size: `5` imports up to five articles plus one pin (six total if available). Set `0` to import only the preferred pin, or nothing if none exists. The newest source-pinned Notices article takes priority, otherwise the newest source pin. Other source pins are treated like ordinary articles and never add extra historical posts beyond that count. Zero-count setup saves one initial source cutoff (creation timestamp and article ID) per guild and imports the preferred pin without notifications. Only successfully published articles are stored in guild publication history; skipped attempts create no rows. `/setup news backfill [count: 1..50]` imports historical articles without consulting that cutoff. Every post ends with a separate message mentioning its matching `SLA:` role. Only newly discovered live articles allow that mention to notify members; setup and manual backfills show the role without pinging it. During setup, the ephemeral reply shows resource creation, source fetching, then processed/total article progress with published and failed counts. Progress updates are throttled to one every two seconds (except completion), and reply failures do not interrupt the import. The separate BullMQ jobs worker triggers bot synchronization every 30 minutes and once at worker startup, using the public API. After the initial import, automatic runs publish missing articles only among the 10 newest across all five categories; use manual backfill to import older articles. New posts include the matching tag, Markdown details and one canonical Netmarble link button. Article text uses Components V2 Text Display. Standalone images and image-only table rows are sent as ordinary image attachments, without V2 wrappers. Text-bearing table rows use V2 containers containing only nonempty cells; labels come only from that table's source headers, never invented Category/Changed defaults. Empty rows are omitted, and headers reset at each table boundary. If an article begins with a table, its opening V2 message contains the canonical link, followed by the row containers. The role mention is sent only after all text, images and table rows. The bot reconciles the Forum pin on every complete source synchronization without reposting: the newest source-pinned Notices article takes priority, otherwise the newest source pin. A category listing failure does not prevent healthy categories from publishing or clear existing pins; pin reconciliation retries on the next complete poll. Long article text is split into Discord-sized messages while preserving hyperlinks, quotes and emphasis. Oversized formatted spans and code blocks are closed and reopened across messages; only a single masked link larger than the message limit falls back to a visible URL. Inline article images are uploaded in reading order when valid; otherwise the original URL is shown at their position. HTML table headers are shown inside the row areas rather than as separate rows; rows connected by a `rowspan` become one container with a bullet list on the right. Images in table rows that also contain text appear as thumbnails beside the text; image-only rows display the images directly. Each 📌 begins a Discord `##` subheading with two blank lines before it; ※ notes become quotes, and leading * notes use small text. No unsupported Markdown tables are emitted. HTML strikethrough uses Discord's `~~text~~`. Existing `/setup logs` is unchanged.
